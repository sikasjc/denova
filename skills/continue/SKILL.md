# 章节续写

根据大纲、角色状态、资料库设定和前文内容续写小说章节。

## 工作流程

1. 直接依据已注入的大纲快照确认长期方向，不必为查看 `setting/outline.md` 重复 read_file
2. 直接依据已注入的角色状态快照确认角色当前位置、身体、心理、目标、持有物和关系等当前状态；这些快照无需重复读取，只有注入被截断需要全文时才按路径读取
3. 如 `setting/chapter-groups/` 下存在当前章节组细纲，优先读取对应细纲，确认本章在组内的作用、冲突、信息揭示和钩子
4. 先用章节组细纲和角色状态判断本章叙事定位，再决定衔接对象：常规线性推进时读取最近 1-2 章实际正文核对连贯；开启新卷、新副本/新单元、单元剧或番外等相对独立的叙事单元时，衔接该单元自身的起点、相关设定和必要跨单元线索，而不是机械读上一章
5. 根据大纲方向、章节组细纲、角色当前状态、资料库长期设定和前文正文创作本章内容；如本轮涉及资料库索引中的相关自动加载条目（基于简介判断），先用 read_lore_items 读取完整资料
6. 使用 write_file 将章节写入 `chapters/` 下符合系统提示章节文件名模板的位置；章节状态只用于 UI 编辑标记，不影响后续章节判断或状态同步
7. 不更改 `setting/outline.md`
8. 若本轮同时生效 `novel-lite` / `novel-standard` / `novel-heavy`，严格按该 preset 的审稿、修订和最终机械验证顺序执行；standalone 使用本 Skill 时只做一次轻量自检和最多一次最小修正，不启动额外审稿流水线。形成最终稿后，在同一轮更新 `setting/character-states.md`（角色当前状态），不等待作者另行确认成章。只有长期设定发生明确变化时，才使用 write_lore_items 批量同步资料库条目

## 写作要求

- 遵循大纲的卷级方向（本卷内容、关键节点、结束状态）；具体的逐章走向以当前章节组细纲为准
- 如有章节组细纲，优先保证本章完成细纲中分配的短期情节功能
- 大纲只作为长期结构和卷级方向参考，续写完成后不要修改大纲文件
- 角色当前状态通过 `setting/character-states.md` 追踪，按角色记录最近出场、当前位置、身体状态、心理状态、当前目标、持有物、能力变化、关系变化和待回收伏笔
- 判断下一章时以实际章节路径和非空正文为准，并结合角色状态快照核对连续性
- 纯错字、标点或措辞润色没有改变角色状态时，无需更新 `character-states.md`
- 资料库只同步角色身份、人设、长期关系、能力体系、世界规则、地点、势力和物品等稳定设定变化，不记录每章后的状态抖动，不写章节规划
- 保持角色性格和说话方式一致
- 与本章真正承接的对象自然衔接（注意情节、时间、地点、人物状态的连贯）：常规推进衔接最近章节，开启新卷/新副本/单元剧/番外时衔接该叙事单元的起点与相关设定
- 注意伏笔的埋设和呼应
- 遵循指定的字数要求
- 章节正文使用纯文本自然段，禁止使用 Markdown 标题、列表、引用、加粗等标记
- 章节开头直接开始叙事，不要输出章节标题

## 章节文件格式

正文内容直接使用自然段，段落间空行分隔。

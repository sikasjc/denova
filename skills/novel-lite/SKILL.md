# novel-lite

用于低延迟正文生成和局部修订。只由主 Agent 执行，不启动任何 subagent。

## 适用范围

- 快速续写、灵感初稿、简单场景、少量对白或段落修改。
- 错字、标点、措辞和结构清晰的局部审阅意见。
- 用户明确更重视速度，且任务不需要跨章审查或复杂规划。

## 执行

- `main agent -> final output`，禁止启动 reviewer、fixer、task 或 General SubAgent。
- 从用户实际指令判断范围；没有 `writing_scope` 字段。除非用户明确说“写下一章”，否则不要假设任务一定是下一章。
- 只读取完成本轮所必需的上下文；需要连续性时使用 `read_file`，涉及资料库时使用 `list_lore_items` / `read_lore_items`。
- 如果用户只要求在对话里生成片段、灵感稿或示例，直接输出正文，不要写入工作区文件。
- 新文件使用 `write_file`；已有章节和审阅意见默认使用 `replace_lines` 最小必要 Patch，优先把最新 `read_file` 返回的 `revision` 作为 `file_revision`，并使用 `start_line` / `end_line` 行号范围。人名、术语等批量字面量替换使用 `replace_text`。只有用户明确要求整章重写时才覆盖已有章节。
- 工具结果出现 `[tool error]`、`string not found`、参数或路径错误时不得宣称已完成；重新读取并重试。
- 正文完成后只允许一次轻量内部自检：核对用户要求、明显连续性错误和明确硬规则，必要时做一次最小修正；不要全文展开问题清单，不要反复读回/grep/修订，不要把轻量自检演化为第二轮完整审稿流程。
- 只有叙事事实或角色状态发生变化时才同步状态文件；纯行文修订不更新。
- 保留用户的控制感，不要过度规划、过度解释，也不要把用户要的初稿改写成另一个故事。

## 输出

- 直接输出用户要求的创作结果。
- 只有用户要求说明，或存在无法满足的重要约束时，才补充简短说明。

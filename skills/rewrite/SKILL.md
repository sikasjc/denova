# 章节重写与修改

根据作者要求修改已有章节。目标是完整满足作者要求，同时最大限度保护未被要求改变的原文。

## 工作流程
1. 直接依据已注入的大纲、进度、角色状态快照和常驻资料库了解上下文，这些快照无需重复 read_file；如修改内容属于当前章节组，读取 `setting/chapter-groups/` 下对应细纲
2. 重新 read_file 读取目标章节的最新完整内容；根据作者要求和审阅意见形成内部 Patch Plan：逐项确定目标位置、必须解决的问题、必须保留的内容、最小必要修改范围，以及意见之间的重叠或冲突
3. 默认使用 edit_file 进行局部修订。同一文件的多个不重叠修改点合并到一次调用；优先把最新 read_file 返回的 revision 作为 file_revision，并使用 start_line/end_line 行号范围，仅在行号不适合定位时才逐字复制 old_string
4. 只有作者明确要求“整章重写 / 全文重写 / 换视角重写 / 彻底改写 / 整体重构”时，才使用 write_file 覆盖已有章节。审阅意见数量多、修改点分散、edit_file 匹配失败，都不自动构成整章重写授权
5. 修改后读回关键片段，逐项检查作者要求和审阅意见是否真正解决，并检查未涉及区域仍然保留、局部衔接自然
6. 只有修改改变了叙事事实、章节摘要或角色当前状态时，才更新 `setting/progress.md` 和 `setting/character-states.md`；纯错字、标点、措辞或局部文风润色无需更新
7. 如果角色身份、人设、长期关系、能力体系、世界规则等稳定设定有变化，使用 write_lore_items 批量同步资料库对应条目
8. 除非作者明确要求调整大纲，不更新 `setting/outline.md`

## 修改范围原则

- 优先级依次是：完整满足作者要求和审阅意见 → 保证修改后上下文连贯 → 保护未涉及内容 → 尽量减少修改范围
- “最小必要改动”不是只做表面替换；允许修改解决问题所必需的邻近句段，但不得顺手润色或改写无关内容
- 多条意见范围重叠时，合并为覆盖这些问题的最小连续文本块；不要扩大到整章
- 意见互相冲突、缺少必要决策，或确实无法通过局部修改解决时，先说明需要扩大的范围和可能失去的内容，请作者确认后再继续
- 必须保留未被要求改变的有效情节节点、人物声线、强段落、伏笔、关键信息和连续性
- 如果 edit_file 返回行号越界、old_string 未找到/不唯一或 revision 冲突，重新 read_file 后按最新行号重建修改并重试；不得因为局部修改失败改用 write_file 覆盖章节

## 修改类型

- **改对话**：调整角色对白，保持性格一致
- **调情节**：修改事件走向，注意前后文连贯
- **换视角**：属于整体重写操作；只有作者明确要求时执行，并尽量保留原有事实、有效场景和信息顺序
- **扩写**：在保持主线不变的前提下丰富细节
- **缩写**：精简冗余描写，保留核心情节
- **风格调整**：改变叙事语调或文风

## 注意事项

- 修改后必须与前后章节保持连贯
- 重大情节变化需提醒作者检查后续章节是否需要调整
- 保持角色性格和说话方式的一致性
- 修改只有影响叙事事实或角色状态时才更新 `setting/progress.md` 和 `setting/character-states.md`；只有长期设定发生明确变化时才用 write_lore_items 更新资料库
- 实质性修改章节时同步检查当前章节组细纲是否还成立；如明显偏离，只提示作者确认是否调整细纲，不要擅自重写长期大纲
- 不要把已完成章节复盘写进 `setting/outline.md`，也不要把未来章节规划写进资料库
- 除非作者明确提出重构主线、调整核心剧情或分卷规划，不轻易更新 `setting/outline.md`（大纲只到卷级，逐章调整属于细纲）
